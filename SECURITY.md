# 安全政策 / Security policy

目前关注 1.2.x 开发线及后续最新发布版本。1.2.0 是发布候选；旧版本与未验证平台不承诺修复时限。社区维护不承诺固定响应期限。

在 [GitHub Security](https://github.com/JDEgg-Bing/Folio/security) 中使用 **Advisories → Report a vulnerability**。维护者必须在公开发布前启用私密漏洞报告；本地文件不能证明该功能已启用。

若看不到入口，请仅创建询问安全联系方式的 Issue，不附漏洞描述、复现步骤、文稿或敏感日志。获得私密渠道后，提供版本、环境、影响范围和最小复现。不要在公开 Issue、PR 或评论披露尚未修复的漏洞。

维护者应私密确认问题、讨论修复及披露时间，修复后发布安全公告，并在报告者同意时致谢。无需提交私人文稿。

## English

Security work focuses on the 1.2.x development line and the latest subsequent release. 1.2.0 is a release candidate. Community maintenance has no guaranteed response or fix deadline.

Use **Advisories → Report a vulnerability** in [GitHub Security](https://github.com/JDEgg-Bing/Folio/security). Maintainers must enable private vulnerability reporting before public release. If absent, open an Issue asking only for a security contact, without vulnerability details, reproduction steps or sensitive data. Share the version, environment, impact and minimal reproduction through the private channel.

Maintainers coordinate fixes and disclosure privately, publish an advisory after remediation and credit reporters with consent. See [GitHub's private reporting guide](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately).
