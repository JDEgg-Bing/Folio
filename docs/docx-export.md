# Word 正式文稿导出

新增模板模式：在 Word 导出窗口导入 DOCX / DOTX、核对自动识别结果、保存并复用模板。使用流程、识别范围、限制和真实 Word 验收见 [Word 模板导出](word-template-export.md)。内置版式仍可选择。

2026-10-02 更新：PDF 与 Word 已采用独立于编辑器的共享正式文稿版式及三个导出预设。以下旧参数及入口说明已被更新，最新设计与验收见 [正式文稿排版](manuscript-export-layout.md)。

文件 → 导出 Word…，选择保存位置后生成 `.docx`。导出包含当前尚未保存的内容；取消不产生文件；成功和资源降级通过现有中文状态提示反馈。导出不修改源码、dirty 状态、保存路径或编辑历史。

## 实现与共享边界

当前 Markdown 快照 → DocumentStructureService 完整 Document Model → exportDocument 版本检查 → DocxExportAdapter → DocxRenderer → OOXML / OPC ZIP → atomicWriteFile。

DocxRenderer 只遍历 Document Model，不解析 Markdown，也不读取编辑器 DOM。正文使用真实 WordprocessingML 文本、段落和样式；不存在整页截图或 HTML altChunk。

原 PDF 导出注册函数小范围提取为 registerManuscriptExport，复用快照构建、资源解析、保存对话框、导出互斥、原子写入和错误处理。两种格式继续共用 WritingAppearance、writingTokens 的标题层级和排版数据，以及 Document Model 的语义和引用编号。PdfRenderer / PdfExportAdapter 保持原样；Word 拥有独立 Renderer / Adapter。

## 原生文档元素

- H1–H6：Word 标题样式与 outlineLvl，标题尽量与后文相邻。
- 中英文正文：宋体 / Times New Roman 等当前指定字体通过 eastAsia、ascii、hAnsi 分配；A4，左右 20 mm、上下 22 mm；顶层正文首行 2 字缩进、两端对齐，按当前字号、行高和段间距换算为 Word 单位。
- 粗体、斜体、删除线、行内代码和代码块：可编辑 run 与段落。代码采用等宽字体，显式换行保留。
- 列表：真实 numbering 定义，保留起始值、嵌套与后续段落。有序和无序列表定义独立；所有 abstractNum 位于 num 实例之前，避免 Word 合并格式。
- 引用：可编辑段落，缩进与克制左边框；分隔线使用段落边框。
- 表格：真实 tbl / tr / tc，三线边框、无竖线、重复表头、单元格对齐、可编辑单元格内容和公式。
- 图片：DOCX 内置 media part 与 drawing 对象，尺寸按正文宽度和页面高度限幅，保持比例；图片和图注居中。PNG / JPEG 原始嵌入，SVG 及其他可识别格式转 PNG。SVG 转换在隔离窗口完成，不依赖网络或原图片继续存在；Windows 显示缩放不影响文稿尺寸。
- 外部链接：原生 hyperlink 与外部 relationship，接受 HTTP / HTTPS / mailto。
- 交叉引用：直接输出 Document Model 的最终标签，图、表、公式、章节编号与现有预览一致；未解析引用保留原文并提示。本轮未实现 Word REF / SEQ 自动更新字段。

## 公式

LaTeX → KaTeX MathML → mathml2omml → 原生 Office Math（OMML）。常见上下标、分式、根号、求和与 aligned 公式均可成为 Word 的可编辑公式对象。块公式居中，编号使用右侧制表位。

转换之前移除 KaTeX 的 LaTeX annotation；通过 disableDecode 保留输入中的 XML 实体，避免 `<`、`&` 等字符破坏文档结构。对布局较特殊的 MathML 标签或命令采取保守降级，在隔离窗口渲染单个公式并嵌入 PNG，图片替代文字保留 LaTeX 源码，同时提示“公式已降级为图片”。降级公式图像不具有原生公式编辑能力。

无效 LaTeX、超出渲染能力的公式保留完整源码并给出诊断，不阻塞其余文档。缺失或无法识别的图片保留占位文字和图注并给出诊断。mathml2omml 的许可、未修改的库和包含源码的 source map 随打包输出提供，见 docx-third-party-notices.md。

## 当前限制

- 引用是导出时的最终文本，导出后在 Word 修改结构不会自动重编号。
- 特殊公式可能转为图片，源码可从图片替代文字恢复；无效公式保留源码。
- SVG 等格式转 PNG，保留图像对象但不保留矢量内部元素编辑能力；动画仅输出静态图像。
- 网络图片不自动下载；未保存 Markdown 的相对图片资源可能无法定位。
- Word 字体由本机提供，不嵌入字体。超宽表格、长公式与超过单页高度的内容仍可能需要在 Word 中调整。
- 未实现页眉页脚配置界面、模板系统、目录页和高级引用字段；本轮未在 LibreOffice / WPS 中实机验收。

本轮仅实现 Word 导出及必要共享基础，验收后停止开发。


## 正式文稿排版修正 2026-10-01

本次只调整 DOCX 输出的主标题、原生页眉页脚及表格排版。以下内容取代上文首次导出验收中的相应样式说明。

- 主标题识别：首个有内容的顶层块为 H1 时使用 Word 原生 Title 样式；忽略引用定义和目标属性。位于前言之后或引用块中的 H1，以及后续 H1，继续使用章节 Heading1。默认主标题居中、黑色、粗体 18 pt，段前 6 pt、段后 15 pt、1.25 倍行距，尽量与后文相邻；字号随正文尺度调整并限制在 16–26 pt。H2/H3 等章节标题继续沿用原有层级。主标题及正文均可编辑。
- 页眉页脚：header1.xml / footer1.xml 为真实 Word header / footer part，通过 relationship、内容类型和节的默认引用连接。每页均使用相同简短标题及“第 PAGE 页”，PAGE 为包含 begin / instruction / separate / result / end 的原生页码字段。页眉页脚使用独立 RunningMatter 样式，9 pt、灰色、居中，距离纸张上下边缘 10 mm，与 22 mm 的正文边距区分。过长页眉按 Unicode 字符缩为 42 字以内。布局默认值集中在 DocxLayout.ts，Word 样式独立，后续可扩展配置，无新增编辑器设置界面。
- 表格：保持原生 tbl / tr / tc、OMML 及可编辑文本。导出时按中文全宽、英文数字近似半宽、公式可视长度估计列权重，兼顾表头与正文的第 80 百分位长度；设置最小宽度、单列最大比例，抑制极端长内容。整数列宽总和严格等于 9638 twips（170 mm），固定网格与每行单元格宽度一致，避免 Word 再次自动缩表或把宽度挤向局部列。
- 对齐：Document Model 增加只读对齐显式标记，记录 Markdown 是否用了冒号，不重新解析 Markdown。明确的左 / 中 / 右对齐保持不变；其余列中至少 80% 非空值为数值时右对齐，纯公式列居中，文本列左对齐。数值支持正负号、小数、科学计数法和常见单位。
- 表格样式：顶线 / 底线 1.25 pt，表头分隔线 0.625 pt，不使用竖线和正文内部横线；单元格上下边距 1.8 pt、左右 4.5 pt，段前段后为 0、1.1 倍行距、垂直居中，不固定行高以免裁切分式；表题居中、段后 3 pt，尽量与表格相邻。图注与表题保留统一字体尺度，图片、公式编号和正文能力保持原样。

## 表格公式对齐修复 2026-10-01

用户指出第一张表第二列的 x² 没有和 210、1 对齐。原因是段落 w:jc 与 Word 原生公式自身的对齐独立；此前只核对了单元格 ParagraphFormat.Alignment，未检查 OMath.Justification，导致遗漏。
