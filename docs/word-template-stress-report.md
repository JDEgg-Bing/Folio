# Word 模板识别改进与压力测试

测试日期：2026-10-02。本轮在 `a8770c7` 压力测试基础上改进识别、确认界面、后台分析和模板复用。历史结果保存在 [原始基线报告](word-template-stress-baseline.md)。

现在可以从没有规范 Heading 样式、但字号、字重、段落特征有区别的模板中建议标题层级。正文选择会排除说明、题注和标题；实际样本与旧样式冲突时，需要单独确认。仍然不能从只有文字描述的要求自动生成未应用过的排版规则，也不能替用户决定两套都有证据的格式哪套才是目标。

## 前后结果

保留原 44 份输入的原始字节，逐份校验 SHA-256；新结果与历史结果分目录保存。原功能组的预期格式没有改变。对于同一格式承担不同角色的样本，检查使用角色相关的示例文字，避免把正确的二级标题映射因首条示例是一级标题而误记为错误。

| 原 29 个功能场景，共 141 个检查点 | 改进前 | 改进后 |
| --- | ---: | ---: |
| 符合预期 | 113 | 137 |
| 未找到映射 | 20 | 3 |
| 与预期不符 | 8 | 1 |
| 高置信错误且未要求确认 | 3 | 0 |

原来符合预期的检查点全部保持通过。原规模组的 8 个成功检查点也保持通过；以前因微小格式差异超限而失败的 1500 样本场景，现在完成分析并通过正文检查。这组有意构造困难反例，不能当作真实学校或教师模板的总体准确率。

新增 8 个压力场景，总数 **52**：不同文字与字体的视觉标题、二级标题先出现、50 条注释之后的英文图题、循环继承、字号与间距合并边界、动态章节页眉，以及 1500／1501 个真正独立候选。新增场景的 9 个格式检查点全部符合；循环继承明确要求确认，1501 候选明确拒绝。

仍保留的失败如下，未把提示或人工确认计为自动正确：

- `12-conflicting-heading`：同一标题样式有较多 16 pt 样本和一个 18 pt 样本。默认建议仍是 16 pt，与人工目标 18 pt 不符，但显示“需确认”，同时提供两套格式；未经单独确认不能保存或导出。人工选择 18 pt 后，Word 实际为 18 pt。
- `13-written-requirements`：正文和两级标题三个检查点均未识别。文档写了字体字号要求，却没有应用这些格式；提示本轮不解析文字要求，正文必须另选已有格式。没有凭空补出要求中的字体。

## 已改善的能力

| 模板情况 | 这轮结果与使用方式 |
| --- | --- |
| 正规命名样式、六级 Heading、自定义大纲名称 | 保持通过；规范定义未被视觉猜测替换 |
| 大量直接格式、无编号的视觉标题 | 根据字号、字重、段落和正文差异建议层级，两级案例符合 |
| 中文括号、罗马／字母、空格编号、长标题 | 原遗漏案例符合；编号需结合标题格式，普通编号清单不再作为标题 |
| Word 自动编号，无规范标题样式 | 读取编号定义并结合视觉格式，两级案例符合 |
| 不同层级格式相同 | 允许共用一个格式候选，用编号与角色相关示例说明层级 |
| 未使用的旧 Heading 与实际格式不同 | 优先实际样本，并要求确认冲突；输出恢复 16 pt |
| 标题多、正文少，或说明多于正文 | 原误判案例恢复为正确正文；不只按段落出现次数选择 |
| 图题／表题很晚出现 | 判断扫描全部段落，界面只展示简短相关样例 |
| 只有缩进与字体线索的引用／列表 | 原案例识别为建议，需要核对；不承诺所有视觉引用都可靠 |
| 两套表格外观 | 新增冲突提示；仍统一采用首表规则，不按用途自动分配 |
| 中英字体、字号、字重、行距、缩进、对齐、分页、页码 | 保持现有识别和导出；代表格式来自真实样本，不取平均值 |

仅直接格式样本允许合并细微差异：段前后／固定行距的组内最大差异 0.5 pt，缩进 0.1 pt，自动行距约 0.042 倍。字体、字号、字重、对齐、大纲、编号等必须相同；不会用不断邻接合并扩大容差。优先选择高频真实样本，同频时选接近中位数的样本。

## 最终用户流程与模板复用

导入 DOCX／DOTX → 自动分析 → 查看正文、主标题、标题层级和题注的相关样例 → 单独确认冲突项 → 保存 → 按此模板导出 Word。

每项最多展示五个推荐格式，加当前选择及回退／搜索入口；其他格式在共享搜索中每次展示十项。状态区分“已识别”“建议核对”“需确认”“已确认”，顶部提示待确认项数量，并可直接定位。确认不涉及手工输入字体字号。

已保存模板继续直接复用，不自动改写旧规则。选择“重新识别”会使用库内原 Word 文件，新建独立草稿，保留原已确认映射，展示新建议；用户只需采用需要改变的建议。旧格式无法重新找到时仍保留为候选。关闭或失败不改写原模板；保存后仍使用同一模板标识，保留名称和默认设置。旧 `version: 1` 记录兼容，不需要原文件还在原路径。

## 规模与桌面响应

本机 Node v24.19.0。改进前是历史单次测量；改进后规模组为三次分析耗时的中位数，包含 XML 校验，不含选择文件和界面绘制。部分测量与打包时间重叠，数值用于本机诊断，不是独立硬件性能基准，也不是所有 Word 文档的绝对最大值。

| 压力条件 | 改进前 | 改进后 |
| --- | --- | --- |
| 100／1000 段，相同规范格式 | 0.13／0.73 秒 | 0.16／0.63 秒 |
| 5000／10000 段，相同规范格式 | 3.30／6.56 秒 | 2.13／4.00 秒 |
| 1499 种细微差异 | 1500 候选，1.85 秒 | 2 候选，1.85 秒 |
| 1500 种细微差异，加 Normal | 超限拒绝 | 2 候选，1.87 秒 |
| 250 层继承 | 4.27 秒 | 0.26 秒 |
| 500／1000 层继承 | 两者均超过 15 秒 | 0.42／0.71 秒 |
| 真正独立的 1500／1501 候选 | 未测 | 1500 能用；1501 明确拒绝 |

分析已移入 worker，每个窗口最多一个活动任务，30 秒超时，worker 堆上限 512 MB；支持取消、异常清理和忽略过期结果。原限制保持：单文件 25 MB、解压后 100 MB、4000 部件、1500 候选。大小边界未全部构造压力输入，不能据此宣称所有上限内文件均能识别。

实际打包应用已验证 worker 能从 app.asar 启动；大量候选下拉框不再全部展开。旧界面约 22517 个 option，新界面最多每角色八项；1500 个真正独立候选的初始界面约 103 个 option。搜索可以找到末尾候选。分析 10000 段时独立模板列表请求约 6.6 ms，取消约 59.7 ms；分析中关闭窗口后应用约 302 ms 退出。实际 IPC 也验证了兼容性勾选不能绕过逐项确认。具体值见本机 `desktop-results.json`。

## Word 原生验收

普通正式报告、科研／技术报告和大量直接格式三类模板均经过桌面导入、保存、再次使用和导出。另在压力组生成 12 份输出，与八份参考共 20 份 DOCX 在 Word 16.0 中打开和渲染，共 25 页；全部页面已检查。

| 案例 | 改进前自动导出 | 本轮自动建议确认后的输出 |
| --- | --- | --- |
| 无编号视觉标题 | 基础标题 17 pt | 恢复模板 16 pt |
| 未使用旧 Heading1 | 24 pt | 恢复实际样本 16 pt；须确认冲突 |
| 说明文字占多数 | 正文 10 pt 楷体 | 正文 11 pt 宋体 |
| 动态章节页眉 | 直接格式标题可能无法匹配旧样式 | 重新关联标题字段，Word 更新后显示“研究背景” |

12 份输出均通过正文和表格文字编辑、保存、重新打开。每份保留一张原生表格、两个 OMML 公式、一个图片对象和四个链接，Markdown source 与 Document Model 均未变。`auto` 表示未改选建议；有冲突的场景仍经过真实模板库的逐项确认，不代表绕过确认自动导出。

STYLEREF 的简单字段和分散在多个 run 的复杂字段均有回归测试，保留开关；未知／歧义目标保持原字段并提示。复杂分节案例仍统一采用末节单栏；两套表格案例仍采用首表，这些限制已展示给用户。

压力图片是微小 PNG 占位样本，仅用于对象保留检查。另重跑包含实际图片和较长 Markdown 的原桌面验收，覆盖正式／技术／直接格式导出、重启复用、普通 DOCX 导出、dirty tracking 与 Undo／Redo。三类较长输出还在 Word 中检查了字体、段落、页边距、页眉页脚、实际图片、两张原生表格、六个 OMML 公式与编辑后重开，输出共八页均已检查。不能把这些结果扩展为所有图片浮动布局均已支持。

## 明确边界

不解析仅用文字写出的排版要求，不重建特殊封面，不保留复杂多节／多栏正文布局，不按不同用途自动分配多套表格样式。复杂文本框、浮动对象、SmartArt、宏、插件和 Strict OOXML 仍受原兼容性限制。视觉线索很弱、角色共享外观且缺少语义证据时，仍可能只能建议或要求确认。
