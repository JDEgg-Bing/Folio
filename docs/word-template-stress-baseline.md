# Word 模板识别压力测试

> 历史阶段记录；其中测试数量、界面与边界只对应当时构建。当前范围以 [1.2.0 发布验收](RELEASE_ACCEPTANCE.md)和[统一规范](DESIGN_SYSTEM.md)为准。原始日志与历史截图留在本地，不随源码公开。

测试日期：2026-10-02。被测识别逻辑：`d428e88`。本轮只增加压力测试、证据和报告，没有修改识别或导出逻辑。

当前能力可以处理规则较多、但样式或大纲证据清晰的模板。没有规范标题样式时，常见的手工编号仍能提供线索。只有视觉上的字号、字重差异，或者只有自然语言写出的要求，目前不足以让软件可靠理解整体文稿规则。最需要修复的是误识别时仍显示“已识别”的情况。

## 测试方法与结论范围

构造 44 份受控 DOCX：29 个功能/歧义场景、15 个规模场景。每份模板先写明预期角色和格式，再调用实际分析器比对。功能组的 141 个预设检查点中，113 个符合预期、20 个未找到映射、8 个与预期不符。自然语言要求组也计入不符结果，用于说明能力边界。这组有意集中构造困难反例，不能作为真实学校/老师模板的总体准确率。

规范组既有 Word Heading 名称，也有仅依赖大纲级别的自定义名称；直接格式组保留视觉差异但移除标题样式/大纲，再逐项改变编号、出现顺序、样本比例和格式噪声。兼容性组检查多分节、多栏和多套表格规则。规模组采用独立进程和 15 秒进程期限，防止极端输入阻塞验收。

另外生成 9 份导出（6 份自动映射、3 份改选已有候选），在 Word 16.0 中打开、渲染、编辑正文与表格文字、保存、重新打开。15 份参考/输出共 19 页已渲染并检查。桌面应用另实际导入视觉标题、残留旧标题样式、1500 个候选和超限候选模板，检查界面显示与错误提示。1500 候选模板经过保存和新建模板库实例读取，原文件字节和确认映射往返一致。

这里的“符合”只覆盖各场景预先声明的检查点，不代表模板所有属性都已全面验证；规模组的正文检查仅检查角色/字号，不能证明细微格式差异的选择正确。图片使用微小 PNG 占位样本，只检查原生对象是否保留，不把它当作复杂图片视觉效果验收。

## 哪些复杂程度已经验证

| 模板表达方式 | 本轮结果 | 使用上的判断 |
| --- | --- | --- |
| 正规命名样式、六级 Heading | 14 个目标角色全部符合 | 常见正式文稿最可靠的路径 |
| 15 类内容角色、中英字体、段落规则、分页、装订线 | 15 个角色全部符合；Word 正文 12 pt 仿宋、一级标题 16 pt | 多个规则并存本身不是主要瓶颈 |
| 样式名称随意，但大纲级别明确 | 六级标题全部符合 | 不要求样式一定叫 Heading |
| 大量直接格式，加“一、/第一章/1.1”手工编号 | 常见两级案例全部符合；六级十进制编号组 8/8 符合 | 没做规范分级也有条件地可用，需要核对 |
| 全无 styles.xml，但格式直接应用且编号明确 | 6/6 符合，并提示缺少样式 | 缺少样式不等于完全无法识别 |
| 100 张表格、正文很少 | 正文与表格文字映射符合 | 表格使用频率没有抢占正文 |
| 标题只有大字/加粗，无编号或大纲 | 两级标题都未识别 | 目前没有按视觉特征建立层级的能力 |
| Word 自动编号，无标题样式/大纲 | 两级标题都未识别 | 显示出的编号不一定存在于段落纯文本中 |
| 多分节、横纵向混合、双栏封面 | 能提示限制；输出统一末节单栏 | 无法还原各节布局或封面内容 |
| 两套不同表格外观 | 只使用第一套；无额外冲突警告 | 摘要说明首表限制，但没有按用途区分多套样式 |
| 只用文字描述“宋体小四、黑体三号” | 0/3 符合目标要求 | 不支持自然语言要求解析；只读实际格式 |

## 已确认的误判和遗漏

1. **未使用的旧样式优先于真实视觉样本。** 模板中实际一级标题 16 pt，残留 Heading1 为 24 pt 且使用次数为零。分析器选中残留样式，界面仍显示“已识别”；Word 输出也实际成为 24 pt。改选 16 pt 段落样本后恢复正确。这个案例同时存在二级标题遗漏。
2. **同名样式格式冲突不会自动降为待确认。** 同一 Heading1 有多种格式版本，算法选用较多样本对应的旧格式，未识别它与当前目标标题的冲突。这是第二个标题高置信误判。
3. **正文选择受样本数量影响。** 12 段标题、1 段正文时，标题的直接格式可能被选为正文；20 段模板说明、6 段长正文时，说明格式被选为正文。后一案例 Word 正文实际成为 10 pt 楷体，改选正确样本后恢复 11 pt 宋体。
4. **首条样本遮蔽后续语义。** 相同格式先出现“使用说明”，再出现“一、研究背景”，一级标题未识别。不同层级字体和段落格式完全相同时，后续二级标题也未识别。
5. **题注样本窗口过短。** 同格式前九段都是注释，图题/表题出现在后面时，两个题注都未识别；大量注释还会影响正文候选。
6. **编号识别覆盖有限。** `1 研究背景` 的一级标题漏识别，括号中文编号和罗马/字母编号的两级标题漏识别；超过 80 字的编号标题也漏识别。普通 `1. 采购事项` 清单反而被推断为一级标题。
7. **视觉引用、列表没有足够语义线索。** 只有缩进、字体变化而没有命名样式时，这两类角色未识别。
8. **封面前置校名可能被当作主标题。** 首段是 16 pt 居中的学校名称，第二段才是 20 pt 真正主标题时，软件选中校名。

这些失败中，多数可以通过改选已有段落格式修复，不必输入字体和行距；但是模板从未实际应用过文字要求所描述的格式时，候选列表中也没有正确答案，单靠确认映射不能补出缺失规则。

## 规模与响应边界

下列为本机单次受控测量，Node v24.19.0；分析时间不含导入对话框和界面绘制。没有声称已找到所有 Word 文档的绝对最大值。

| 压力条件 | 实际分析/界面结果 |
| --- | --- |
| 100 段，重复同一正文格式 | 约 0.13 秒 |
| 1,000 段，同一格式 | 约 0.73 秒 |
| 5,000 段，同一格式 | 约 3.30 秒 |
| 10,000 段，同一格式 | 约 6.56 秒，正文映射符合 |
| 100 种近似视觉格式 | 约 0.24 秒，101 个候选 |
| 500 种近似视觉格式 | 约 0.67 秒，501 个候选 |
| 1,000 种近似视觉格式 | 约 1.30 秒，1001 个候选 |
| 1,499 种近似视觉格式 | 约 1.85 秒，1500 个候选；桌面导入到显示约 2.13 秒 |
| 1,500 种直接格式，加 Normal | 总候选超限，明确拒绝 |
| 样式继承 10 / 50 / 100 层 | 约 0.07 / 0.28 / 0.84 秒 |
| 样式继承 250 层 | 约 4.27 秒 |
| 样式继承 500 / 1,000 层 | 都未在 15 秒进程期限内完成，测试进程被终止 |

格式噪声样本的段前/后最大差异仅 0.45 pt、行距差异 0.0375 倍、首行缩进差异 0.05 pt，但仍被拆成独立候选。每项映射下拉框含 1501 个选项，整个对话框约 22517 个 option；能显示，不代表用户能轻松筛选。确认保存约 0.07 秒，新库实例读取约 0.01 秒，复用没有重新分析。

现有硬性限制是单文件 25 MB、解压后 100 MB、4000 个部件、1500 个格式候选。其中本轮直接压测的是候选上限；没有构造所有文件大小极限。产品本身没有这次测试脚本的 15 秒超时保护，分析同步运行于主进程，深层继承存在长时间占用主进程的风险。

9 份输出均通过 Word 打开与正文/表格文字编辑、保存、重开的往返。每份包含 1 张原生表格、2 个原生 OMML 公式、1 个图片对象、4 个链接；模板页眉和页码字段保留。多节双栏输入的输出确实成为一个纵向单栏节；两套表格输入的输出采用首表蓝灰底纹规则。所有导出均检查 Markdown source 和 Document Model 未变。

原生验收起初在 Windows PowerShell 5 的 Word 调用中阻塞；改用本机 PowerShell 7 后完成。另一个验收断言起初在公式单元格插入 ASCII 标记，而 Word 会把数学字母显示为数学斜体 Unicode；最终改为编辑普通文字单元格，并验证保存重开。本轮未把这两个验收工具问题算成产品失败。

## 复现与下一步范围

```powershell
node scripts/word-template-stress.cjs
node scripts/word-template-stress-verify.cjs
# 设置 MARKDOWN_PLAYWRIGHT_MODULE，或使用已有 playwright 安装，再验收已打包桌面应用：
node scripts/word-template-stress-verify.cjs out/word-template-stress --desktop
# 在 PowerShell 7 中执行；需要本机 Word：
./scripts/word-template-stress-word.ps1
# 使用含 pypdfium2 和 Pillow 的 Python：
python scripts/word-template-stress-pages.py
```

可给压力脚本第三个参数按 ID 前缀重跑部分场景；Word 脚本支持 `-Only` 前缀。重复运行会替换隔离的测试证据，不接触真实用户模板库。

优先改进应是：实际使用证据与旧样式冲突时降低置信度；利用字号/字重/段落特征、完整样本和 Word 编号定义推断非规范标题；区分说明、封面和正文；合并近似格式；缓存继承分析并移出主进程，加超时/取消。自然语言排版要求解析和复杂封面重建属于新的能力，不能用当前结果宣称已经支持。
